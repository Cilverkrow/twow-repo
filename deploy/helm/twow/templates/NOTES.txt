Two things this chart cannot do for you:

1. Client data. dbc/maps/vmaps/mmaps are extracted from your own game client and
   are never in an image. Populate the client-data volume before the pods can
   serve anything:

     kubectl exec -it {{ include "twow.fullname" . }}-mangosd-0 -- ls /opt/turtle/data

   Locally, `make extract` in the repo root produces the same tree.

2. The realmlist row. tw_logon.realmlist is created empty. Without a row the
   realm never appears; with the wrong port the client hangs before character
   select. port must equal {{ .Values.mangosd.service.port }} and realmflags must be 0:

     INSERT INTO {{ .Values.database.names.logon }}.realmlist
       (name, address, port, icon, realmflags, timezone, allowedSecurityLevel)
     VALUES ('{{ .Values.realm.name }}', '{{ .Values.realm.address | default "<client-reachable address>" }}', {{ .Values.mangosd.service.port }}, 0, 0, 1, 0);

Console access (the FIFO the entrypoint holds open, which is also what stops
mangosd exiting on EOF):

  kubectl exec {{ include "twow.fullname" . }}-mangosd-0 -- \
    sh -c 'echo "server info" > /opt/turtle/run/mangosd.in'
  kubectl logs {{ include "twow.fullname" . }}-mangosd-0
